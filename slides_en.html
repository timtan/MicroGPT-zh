Warm-up 0Only two kinds of number in the code

預 0・新手最常糊掉的一組
  • 一句話：左邊是模型會的東西，右邊是它現在正在想的東西。訓練＝把左邊那 4,192 個調好；推論＝拿左邊去算出右邊。
  • 之後每看到新變數就問：左邊還是右邊？state_dict 開頭的是左邊，其餘幾乎都是右邊。
  • 先埋伏筆：keys／values 仍是算出來的中間值，只因 cache 延長生命週期而活過一輪（圖 9 收）。
  • 尾鉤：每次呼叫的主線狀態，都沿著同一個 16 維 x 前進——下一頁就是它。

Warm-up 1Every call moves along one 16-dimensional x

預 1・主角
  • 別被「16 維向量」四個字嚇到：它就是一個長度 16 的 list，沒有更多了。
  • 整個模型跑一輪＝這個 list 被加料三次（＋位置、＋前文的料、＋加工的料）。這頁不解釋那兩份料哪來的——它們是圖 4、圖 5 的主題，這裡只先讓聽眾看到「動詞永遠是加」。
  • 加完三次、進 lm_head 之前：「此刻的意義」和「對下一個字母的預測」同時濃縮在這 16 個數字裡——圖 7 揭曉這兩件事是同一件事。
  • 尾鉤：這個 x 從頭到尾只會被三種運算對待。下一頁開始，一種一頁。

預 2・相加
  • 相加的意義：把兩份理解疊在一起——字母的意義＋位置的感覺＝帶著位置的字母意義。
  • 對寫過程式的人：殘差就是 x += 修正，不是 x = 修正。全場沒有任何一步會「洗掉」x。
  • 句型順帶學：zip＝兩個 list 並排走；list comprehension＝對每一格做同一件事。
  • 尾鉤：加法只會疊、不會變——想變出「我在找母音」這種新理解，得靠第二種運算：相乘。

Warm-up 3a② Multiplication I: the dot product

預 3a・內積
  • 很多人不是不會，只是很久沒算數學了。所以這一頁用真數字算完一次，不趕。
  • 整個內積就一句話：兩個 16 維向量進去、一個數字出來。在模型裡，這個數字被當作相容度分數。
  • 先埋：等一下 attention 用它判斷「目前的 q 應該向前面哪個 k 拿多少資訊」。
  • 順手埋第二件事（圖 7 會用到）：內積大小同時受方向與數值尺度影響。把 w 每個數字都乘兩倍，內積也跟著變兩倍。
  • 尾鉤：一個內積只給一個數字，但主幹上要的是 16 個數字——所以要做 16 次，那就是矩陣。

Warm-up 3b② Multiplication II: a matrix is a stack

預 3b・矩陣
  • 一句話：矩陣就是一疊向量，相乘就是拿 x 跟每一列各做一次內積。
  • Python 沒有矩陣型別，就是 list 裡面裝 list——左圖那個寫法，跟右邊的數學是同一件事。
  • 形狀怎麼看：矩陣有幾列，出來就是幾個數字。fc1 有 64 列，所以 16 個數字進去、64 個出來。
  • 「16 維 × 矩陣能算出什麼」，取決於矩陣裡那些列是什麼——而那些列是訓練學出來的。
  • 尾鉤：算出來的數字正負混雜、大小不一——誰來過濾？下一頁的第三種運算。

預 4a・非線性
  • relu 就像神經網路裡的門檻——在 MLP 的兩次線性轉換之間加入分情況的能力；拿掉它，兩次線性轉換可以合併成一次。
  • 相加是疊、相乘是換角度，都還是線性的——非線性是唯一能製造「分情況」的地方。另外還有 softmax（attention／抽樣見）和下一頁的 rmsnorm，它們都是配角，「只有三種運算」仍然成立。
  • 收尾一句：運算只有三種、數字只有 4,192 個。之後每張圖都可以問「這一步用的是哪一種運算？」——Attention＝用這三種搬前文、MLP＝用這三種想。
  • 尾鉤：三種運算講完了，但還有一個零參數的配角每次內積前都會上工——下一頁。

預 4b・音控台
  • rmsnorm 為什麼存在：相加一直疊、相乘會放大縮小，x 的音量會漂移；音量一漂，內積沒有共同尺度、softmax 被極端值綁架。所以每次做內積前先過音控。
  • 零參數＝它不是知識，是水電：4,192 個數字裡沒有半個屬於它。這一點要講出來，否則聽眾會以為又多了一批要學的參數。
  • 三個上工位置先點一下就好，圖 4c 的接線圖會再看到它們——這裡只要建立「內積前先統一音量」這個習慣。
  • 這頁講快一點，它是配角；重點是不要讓 rmsnorm 在後面的圖裡變成沒交代過的陌生字。

圖 4・一橫一縱
  • 「一橫一縱」就是整個 Transformer 的骨架：Attention 負責搬運、MLP 負責加工，兩者交替就是全部。（這句話在圖 6 會再出現，那時它會有更深的意思。）

圖 4b・為什麼要四個人
  • 單頭做不到這件事：16 個輸出維度被迫共用同一組注意力權重，只能「全看剛剛那個」或「全看開頭」，或糊成一團平均。

圖 5・MLP
  • 回到預 3b：fc1 就是一個 64 列的矩陣——每一列都是一個偵測器，跟 x 做一次內積問一題。
  • 為什麼要先撐胖再壓瘦？（預 4a 欠的論證，在這裡還。不要講矩陣乘法，講聽眾手上已經有的東西：）fc1 做的是「x 跟每一列做內積」，fc2 做的也是「跟每一列做內積」。如果中間沒有那道門檻，整段就只是內積接內積——而內積接內積，永遠可以事先算好一組列、一次做完。撐到 64 維再壓回 16 維完全白做。
  • 加了 relu 就不一樣了：哪些偵測器有開口，是看 x 才知道的。同一段程式對不同的 x 表現得像不同的規則——這是「事先算好一組列」永遠做不到的事。這就是「分情況」的全部意思。
  • 把 MLP 看成64 個軟性特徵偵測器：每個偵測器給一個連續分數，relu 關掉負值，剩下的啟動再一起寫回主幹；不是 64 條可逐字讀出的離散規則。
  • 以英文名字想像：某個神經元專門偵測「剛剛連續兩個子音」，一觸發就往主幹加上「接下來該是母音了」的方向。

圖 10・訓練
  • 訓練從頭到尾只有一個任務——猜下一個字母。沒人教母音子音、沒人教名字長度，全部是順便學會的。
  • losses 是整個名字每個位置各算一次再平均：一筆資料提供 5 個學習訊號，不是 1 個。
  • backward() 這格不要再解釋一次——圖 9.5 剛手算過。一句話帶過：「同一套鏈式法則反向走過整張計算圖，一次累積 4,192 個梯度。」
  • 訓練時使用的是真實序列的前一個 token，不是模型剛抽到的 token；梯度會一路穿過 lm_head、MLP、attention、embedding。
  • loss 為什麼取 −log：機率 1 → 罰 0；機率 0.9 → 罰 0.1；機率 0.01 → 罰 4.6。越是把正確答案說成不可能，罰得越兇。就這樣，不用講 cross entropy。
  • Adam 沒有黑魔法：就是「梯度的移動平均 ÷ 梯度平方的移動平均開根號」。不懂也不影響理解全場——它只決定「挪多大一步」，方向早在 backward() 就算完了。真的沒時間就說這一句然後跳過右欄下半。
  • 撞名提醒：Adam 的 m／v 這個 v 跟 attention 的 v 純粹撞名——作者省字母重用了，先點破，聽眾就不會亂連結。
The whole Transformer in three lines
Attention moves decides where to take information from
MLP refines decides what to make of what it took
Residual adds both only add to the main line, never overwrite
Training: the correct next letter → loss → backward → Adam → update all 4,192 parameters
More layers ＝ the same thing again　·　Today's large models ＝ the same thing, orders of magnitude bigger

  • 收全場：三個顏色跟著三個角色走了一整場——橘色搬運、綠色加工、藍色主幹。

  • 多層 Transformer＝同一件事再做一次；大模型＝同一件事做大很多倍。

補充
  • 這三題都有數字撐著，才適合說「模型自己學會了沒人教它的東西」。
  • 中文實驗：名字只有 2–5 個字，block_size 變小、vocab 爆增——參數量的分佈完全變樣。
  • 有人問「128K context 怎麼來的」時才講（圖 3b 刻意留的）：wpe 這種查表法，超過列數就是 IndexError。現代模型改成不查表——把位置變成一個旋轉角度，直接轉在 q 和 k 上（RoPE）。角度可以一直往下算，所以能外推到訓練時沒看過的長度。這需要聽眾已經懂 q/k，所以擺在最後。
